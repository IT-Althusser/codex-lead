# codex-lead

一个以“审查方”身份调度 **Codex 桌面版** 完成项目实施的技能：由 Codex 负责调查、写代码、跑测试，本技能负责确认需求、下达任务、独立审查真实产物、决定返工，最后按授权提交或推送。

本技能不直接改项目代码，也不使用独立 `codex exec`、PTY 或其它未连接桌面的后端替代；所有项目消息都进入你可以在桌面看到的专用会话。

## 适用场景

- 让 Codex 实现/修改某个功能、修某个 issue
- 需要“下任务 → 独立审查 → 返工”这条完整闭环
- 需要审查有据可查（读真实 diff、日志、测试退出码），而不是只信“已完成”

不适用于单纯讨论 Codex 用法、工具选型或纯问答。

## 环境要求

- Windows，已安装并登录 Codex 桌面版
- Python 3（脚本按 `python -X utf8 -I` 方式运行）
- PowerShell 5+
- 桌面控制桥监听地址：`ws://127.0.0.1:18765`（默认）

## 目录结构

```
codex-lead/
├── SKILL.md                    # 入口：触发条件、参数、流程指引
├── WORKFLOW.md                 # 完整流程与不可越界的职责边界
├── references/
│   ├── desktop.md              # 桌面连接、会话、审批、状态读取
│   └── prompts.md              # 下任务、返工、提交等消息模板
└── scripts/
    ├── desktop.py              # 调度工具：状态/发送/读取/中断
    ├── launch_desktop.ps1      # 启动或唤起 Codex 桌面
    └── test_desktop.py         # 离线测试：不连桌面、不跑项目命令
```

## 使用方式

在对话中直接提出委派需求即可，无需斜杠命令；也可显式调用：

```
/codex-lead <需求> <项目绝对路径> [约束/验收条件]
```

技能被触发后会读取 `WORKFLOW.md`，按“确认 → 实施 → 独立审查 → 返工 → 可选提交”的顺序推进。

## 职责边界

- Codex：项目调查、实现方案细化、改代码/文档/配置、装依赖、跑测试与构建、修复问题。
- 本技能：理解目标、划定范围与验收条件、下达任务、跟进状态、独立审查实际产物、发返工单、汇报结论。
- 提交/推送/建 PR 需单独明确授权，三者不自动串联。

指令层面的角色约束，不等同于操作系统级沙箱。

## 运行记录

默认写入 `D:\codex-content\<当天日期>\codex-lead\<任务标识>\`：

- `task.json`：任务与会话绑定
- 每回合的 `state.json` / `result.json` / `events.jsonl`：调度与状态证据
- `request.md`：实际发到桌面会话的项目指令

调度信息只留在记录里，不混入给 Codex 的项目提示词。

## 离线测试

```powershell
python -X utf8 -I scripts/test_desktop.py
```

仅验证调度状态机与消息组装，不连接桌面、不执行任何项目命令。
