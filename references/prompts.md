# 干净的项目消息模板

先整理用户的真实目标及最后批准计划，只使用需要的模板，不发送本文件全部内容。花括号是填写位置，不把占位符发送给Codex。消息标题用于桌面辨认，不使用内部调度编号作为任务名称。

## 实施

```markdown
# 实施：{任务名称}

请完成以下修改，完成后由我审查，暂不提交或推送。

## 目标与范围
- 项目：{绝对路径}
- 需求依据：{issue/需求的准确正文要点及链接}
- 本次修改：{用户确认的范围}
- 不修改：{明确排除项}

## 已确认计划
{最后批准的计划或项目内可读取的计划文件；不要混入废弃方案}

## 验收条件
{可观察结果、关键异常/兼容路径及必要测试}

## 工作要求
先读取项目规则并检查工作区，保留现有修改。{使用已确认任务分支/从指定基准建立任务分支}，不在默认分支或无关任务分支修改。
请完成实现、运行相关验证并修正失败。不能在本范围内解决的关键阻塞请给出具体证据，不扩大需求或伪造成功。

## 完成报告
列出修改文件、实际验证命令及结果、未覆盖项，并对照验收条件说明完成情况。不要提交或推送，等待我的审查。
```

用户已明确批准计划后，直接下达实施任务，不把计划再次发送为“请只分析”。用户仅要求调查时，将任务明确改为只读，不运行会产生项目文件的命令。

## 实质审查与返工

```markdown
# 审查：{任务名称} — 需要修改

我检查了实际改动及验证证据，以下问题尚未满足验收：

1. {文件:行号/函数}
   - 触发条件：{具体输入/并发/环境}
   - 当前结果：{已核实缺陷}
   - 预期结果：{对应需求}
   - 复测：{应证明的真实行为，不替它写成品补丁}

请在当前任务分支修复以上问题，保留已正确的修改，不扩大范围。完成后重新运行受影响验证，报告结果及剩余限制。暂不提交或推送，我会再次审查。
```

不把未经验证的猜想当确定缺陷；需要证据时让Codex复现并报告。返工不是发送整份最初任务，也不是“再完善一下”。

## 中断后继续

```markdown
# 继续：{任务名称}

请先核对任务分支上的现有修改，再完成剩余工作：
- {确实未完成的实现/测试/返工项}

保留已有正确内容，不重建任务分支或重复已完成操作。完成后报告实际验证及限制，暂不提交或推送。
```

原回合是否结束由mentor通过工具核对；不把断线、审批参数、TCP或CLI诊断写进这条消息。

## 验收通过（无发布授权）

```markdown
# 审查通过：{任务名称}

我已核对{实际审查范围}，现有实现满足{具体验收条件}。
验证证据：{命令/报告及结果摘要}。
仍有限制：{未验证内容或无}。

本次未授权提交或推送，请保留任务分支上的修改，不执行发布操作。
```

## 已授权的提交/推送

```markdown
# 交付：{任务名称}

实现已通过我的审查。按用户授权执行：{仅commit / commit并push / 另获授权的PR范围}。
- 任务分支：{明确名称}
- 仓库：{明确remote URL}
- 远端目标：{任务分支，不是默认分支}
- 只提交：{本任务文件范围}

先检查差异和分支，不纳入用户的无关修改，不强推、不推上游或默认分支，遵循当前项目与用户提交规则。报告commit SHA和实际推送结果；未授权的PR等操作不要执行。
```

前提是mentor已独立审查，而不是只读Codex自述“完成”。提交后还要只读核对真实commit及远端任务分支。
