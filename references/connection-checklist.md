# 连接检查表

本表供 mentor 执行调度时使用，不发送给 Codex，不包含具体项目或会话信息。

## 执行前一次检查完整链路

1. 用`desktop.py doctor`检查当前解释器依赖、桌面实际连接和共享后端协议。`ready: false`时不发项目任务，不先进入实施再修连接。
2. 后端未就绪时核实当前桌面配套`codex.exe`，只启动一个共享后端，使用`backend`确认initialize；不依赖旧安装版本目录。
3. 桌面未连共享后端时，保存工作并经授权正常退出/启动。`launch_desktop.ps1`先查后端、再启动、再等待真实连接；返回启动PID不算连接成功。
4. 首次派单由`send`在同一连接创建会话并启动首轮，后续准确恢复已记录会话。对实际返回的目录、沙箱、审批策略及审批主体再验证，符合才发送项目任务。
5. 在桌面定位本任务，确认任务消息和过程可见；连接证据不能代替GUI可见性确认。后续审查/返工沿用该任务，不创建重复实现回合。

此流程减少重复排障，不保证缺依赖、用户未退出桌面、系统内存紧张或服务升级时也能无条件连接。遇到边界条件给出明确阻塞，不能用降级CLI或扩大权限换取表面成功。

## 故障原因与处理

| 现象/诊断 | 原因或必须区分的条件 | 处理与防止复发 |
| --- | --- | --- |
| `WEBSOCKETS_MISSING` / `WEBSOCKETS_INCOMPATIBLE` | 选错解释器、依赖缺失或连接接口变化 | 先核对同一解释器的包和接口；使用已有依赖或取得安装授权，不在失败连接上反复重试 |
| `BACKEND_UNAVAILABLE`，如10061 | 共享后端没有监听或已停止 | 核对端口/进程，只启动一个后端；启动后initialize成功再连桌面，不从桌面进程存在推测后端可用 |
| `BACKEND_PROTOCOL_FAILED` | 端口上不是预期app-server或协议版本不兼容 | 核对服务身份和当前Schema，不自动换后端/复制凭据 |
| `DESKTOP_NOT_RUNNING` | 未找到可核实的Codex桌面进程 | 后端就绪后经授权启动桌面，不把codex.exe后端本身当桌面 |
| `DESKTOP_NOT_SHARED` | 桌面可能使用自己的stdio后端，或尚未完成连接 | 正常重连到同一回环地址并检查Established连接；只共享历史目录不算通过 |
| 正常关闭后进程仍在 | 关闭窗口可能只是隐藏到托盘 | 提醒用户完全退出后再启动，不反复CloseMainWindow、不强杀、不启动第二实例 |
| `no rollout found` | 全新会话在首轮前尚无可恢复历史，跨连接resume过早 | 首次thread/start与turn/start放同一连接；不能创建空会话后换连接恢复 |
| 恢复后收不到通知 | 新连接未resume订阅，不能凭loaded列表判断 | 每次后续派单先准确resume；派单工具不跳过此步骤 |
| 等待审批时ping timeout | 用户等待时间超过客户端心跳期限 | 使用无周期ping的本机连接及显式审批超时；缺决定只取消，不自动批准 |
| 声称on-request但实际never或自动审批 | 启动参数没有代表最终实际会话策略 | 创建/恢复响应必须确认on-request、user审批、预期沙箱及项目，失败不发送项目消息；不使用独立CLI替代 |
| `.git`写入拒绝或GitHub连接失败 | 项目命令权限/网络问题，不等于桌面断连；API可访问也不证明Git传输可用 | 通过正常审批核对具体命令，拒绝或失败如实报告；不反复重启桌面、不改全局代理/ACL、不换执行者绕过限制 |
| 未保存的结果/应答丢失 | 模型任务可能仍在运行，不能据调度进程失败猜测结束 | recover原thread/turn；未知状态不重发，先查历史与磁盘内容 |
| 系统内存不足停止后端 | 外部资源中断，不是代码/测试结论 | 保留改动与记录，遵守系统要求；用户要求恢复后再启动，先核实原回合，不自动无限重启或关闭系统保护 |

## 成功标准

- `backendReady`：只证明依赖与共享后端initialize成功。
- doctor的`ready: true`：依赖、桌面实际共享连接和后端握手均通过，不代表项目Git/测试或模型任务成功。
- 派单成功：收到并持久保存准确threadId/turnId；实际会话权限通过核对，项目正文原样发到桌面。
- 项目完成：目标回合结束后，mentor检查真实代码与验证证据并通过验收。

不要将以上四种状态合并成“连接成功所以任务完成”。
